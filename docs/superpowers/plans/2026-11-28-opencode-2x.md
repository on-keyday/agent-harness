# opencode 2.x Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the opencode preset, the opencode transcript store and the release check work against opencode 2.x.

**Architecture:** Three independent edits: argv templates in the preset table, the two CLI invocations in the transcript store, and the release selector in the sandbox release check. No wire or schema change.

**Tech Stack:** Python (`scripts/`), Go (`runner/transcript`).

**Spec:** `docs/superpowers/specs/2026-11-28-opencode-2x-design.md`

## Global Constraints

- 2.x only; no version detection, no 1.x fallback.
- `--standalone` on every opencode launch the harness makes: all four preset templates, `session list`, `session export`.
- `session list` carries `-n 2147483647` (2.x rejects 0; default is 100).
- Verified version recorded as opencode 2.4.2.

## Review Focus

- A project with more than 100 opencode sessions across worktrees: an older task's session must still be listed — Task 2 asserts the `-n` argument reaches the binary.
- An operator's own opencode service already running on the host: harness launches must not attach to it — Task 1 asserts `--standalone` on all four templates, `sandbox-opencode` included.
- The runner listing transcripts must not start a background service — Task 2 asserts `--standalone` on both calls.
- A 1.x patch release published after a 2.x release (v1.19.6 was published after v2.3.0): the release check must still pick 2.x — Task 3 orders by version, not by date.
- Non-`v*` tags in the same repo (`process-daemon-v0.6.0`) must never be selected — Task 3 test.
